Hướng dẫn Email Templates

① Cơ chế hoạt động

Vì sao sửa nội dung không cần đụng code.

Một quy tắc duy nhất, áp dụng cho cả 7 mail:

Bảng Email Templates → Agent đọc + thay biến + nối footer → ghi vào field "Email subject" / "Email body" của dự án → Automation gửi 2 field đó đi.
  • Nội dung (chữ nghĩa) sống trong bảng Email Templates → PO sửa.
  • Việc thay biến + gửi do hệ thống lo → ổn định, hiếm khi đổi.
  • Mọi automation gửi mail đều giống nhau: chỉ gửi {Email subject} + {Email body}; khác nhau ở người nhận và file đính kèm.
Hệ quả: đổi câu chữ 1 mail = sửa 1 ô trong bảng, hiệu lực ngay lần gửi kế tiếp. Không build, không deploy.

② PO sửa nội dung email

Mở bảng Email Templates (tab Data) hoặc page "Email Templates (Admin)" trong Cổng Merch.

Mỗi dòng = 1 loại mail. Các cột:

CộtÝ nghĩa
MãKhoá loại mail (bo_sung, proposal…). KHÔNG đổi.
TênNhãn dễ đọc cho người dùng. Sửa thoải mái.
SubjectTiêu đề mail. Được chèn biến {{...}}.
BodyNội dung mail. Được chèn biến. Footer tự nối ở cuối — không cần gõ.
Biến dùng đượcLiệt kê biến hợp lệ cho riêng dòng đó (tham khảo khi sửa).

Sửa nội dung: bấm vào ô Subject hoặc Body → gõ lại → xong. Muốn chèn dữ liệu động thì gõ tên biến trong cặp ngoặc, ví dụ {{ten_project}}.

Footer dùng chung: sửa ở dòng có Mã = footer (gồm cả email hỗ trợ) — đổi 1 lần áp dụng mọi mail.

⑤ Admin: cấu hình automation gửi mail

Mỗi automation gửi mail trỏ Subject/Message vào 2 field buffer.

Với 6 mail qua app (bo_sung, clarify, proposal, plan, brief, pic): trong automation tương ứng → step Send an email:

1
Subject = chèn field {Email subject} (xoá nội dung gõ tay cũ).
2
Message = chèn field {Email body}.
3
Giữ nguyên người nhận (requester = Created by → Email; PIC = đầu mối PIC) và file đính kèm (proposal/plan/brief).

Bảng map automation ↔ loại mail:

AutomationTriggerMã template
Gửi proposal cho requesterFile proposal đính kèmproposal
Gửi brief cho requesterFile brief design đính kèmbrief
Gửi plan cho PICFile plan sản xuất đính kèmplan
Báo PICCần PIC xử lý ✓pic
Cần phản hồi để tiếp tụccờ "Gửi mail làm rõ" ✓clarify
Gửi mail bổ sungcờ "Gửi mail bổ sung" ✓bo_sung
Automation "Gửi mail bổ sung": cách nhanh = Duplicate "Cần phản hồi để tiếp tục", rồi đổi điều kiện trigger sang cờ Gửi mail bổ sung và đổi field untick ở step Update record sang Gửi mail bổ sung.

⑥ Mail quá hạn — dùng Run script

Scheduled Automation chạy theo lịch, app không nằm trong luồng → tự render bằng script.

Trong automation Quá hạn duyệt → báo requester, phần lặp mỗi record (repeating group) thêm 1 step "Run a script" TRƯỚC Send email.

Input variables của step (lấy từ record của repeating group):

NameValue
maProjectfield Mã project
tenProjectfield Tên project
gamefield Game → name
tenNguoiGuifield Created by → name
hanDuyetfield Deadline phê duyệt

Script:

let cfg = input.config(); let templates = base.getTable("Email Templates"); let tq = await templates.selectRecordsAsync({ fields: ["Mã", "Subject", "Body"] }); let map = {}; for (let r of tq.records) { let ma = r.getCellValueAsString("Mã"); if (ma) map[ma] = { s: r.getCellValueAsString("Subject"), b: r.getCellValueAsString("Body") }; } let tpl = map["qua_han"] || { s: "[{{ma_project}}] Quá hạn duyệt proposal", b: "Proposal đã quá hạn duyệt." }; let footer = (map["footer"] && map["footer"].b) || "Merch Agent · AMC Team · VNGGames"; function fmtDate(v) { if (!v) return ""; let s = String(v); let m = s.match(/^(\d{4})-(\d{2})-(\d{2})/); return m ? `${m[3]}/${m[2]}/${m[1]}` : s; } let vars = { ma_project: cfg.maProject || "", ten_project: cfg.tenProject || "", game: cfg.game || "", ten_nguoi_gui: cfg.tenNguoiGui || "Anh/Chị", han_duyet: fmtDate(cfg.hanDuyet), }; function sub(t) { return (t || "").replace(/\{\{(\w+)\}\}/g, (m, k) => (k in vars) ? vars[k] : m); } output.set("subject", sub(tpl.s)); output.set("body", sub(tpl.b).trimEnd() + "\n\n" + sub(footer));

Sau đó Send email: Subject = {Run script → subject}, Message = {Run script → body} (đọc từ output của script, KHÔNG đọc field record).

Vì sao đọc từ output, không từ field? Repeating group đọc record ở thời điểm "Find" → giá trị script vừa ghi vào field chưa được đọc lại trong cùng vòng lặp. Dùng output của script là chắc ăn.

⑦ Tránh làm hỏng

Vài thao tác dễ vô tình phá hệ thống.
ĐỪNG:
  • Đổi giá trị cột Mã (bo_sung/clarify/proposal/plan/brief/pic/qua_han/footer) — hệ thống dò đúng chuỗi này; đổi = mail rơi về template mặc định.
  • Xoá dòng footer — mọi mail mất footer (rơi footer mặc định).
  • Sửa tay 2 field Email subject / Email body trên dự án — chúng do hệ thống ghi đè.
Tự do làm:
  • Sửa Subject, Body, Tên, Biến dùng được của bất kỳ dòng nào.
  • Sửa dòng footer (kể cả email hỗ trợ).

Thêm dòng Mã mới sẽ không có tác dụng trừ khi có lập trình tham chiếu (không tự thêm loại mail mới được).

⑧ FAQ / khắc phục

Mail gửi đi rỗng (Subject/Message trống)?

Automation đang đọc field Email subject/body nhưng record chưa được agent ghi (hoặc, với mail quá hạn, Send email đọc field thay vì output script). Kiểm tra Send email trỏ đúng nguồn.

Biến {{ten_bien}} hiện nguyên trong mail?

Gõ sai tên biến → hệ thống giữ nguyên thay vì lỗi. Đối chiếu lại danh sách biến ở mục ③.

Sửa template xong bao lâu có hiệu lực?

Ngay lần gửi kế tiếp — hệ thống đọc bảng mỗi lần render, không cache.

Script quá hạn báo "No record matching … found in query"?

Đó là cách cũ (query lại Projects + getRecord). Dùng bản script ở mục ⑥ — truyền thẳng giá trị field qua Input variables, không query Projects nữa.

Footer bị trùng / có 2 chữ ký?

Đừng gõ footer/chữ ký trong cột Body — footer tự nối. Body chỉ chứa phần nội dung riêng.
